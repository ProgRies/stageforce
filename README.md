# Stage Force · 0.1.3

A self-hosted, shared CRM for a small team. The existing frosted desktop interface now uses SQLite on your server. It does not need Google Sheets, ChatGPT, an AI provider, Gmail credentials or a mail-sending service.

## Included

- System/light/dark appearance selector, remembered per browser. System mode is the default and follows live browser preferences. Dark mode uses a bounded canvas signal-field animation with pause, hidden-tab suspension and reduced-motion support.
- Larger working text and controls, with a full-width responsive desktop layout.

- Individual local accounts; CLI account creation, password changes and disabling.
- Organisation search across master data, contacts, notes, email bodies and source references.
- Organisation/contact editing, organisation links, FastBill URL shortcuts, manual review indicators.
- Daily call queues, customer follow-ups and lead calls; reached/missed outcomes recorded with the signed-in colleague.
- `.eml` review: sender/recipients, date, incoming/outgoing direction, conservative quote removal, original-text comparison, optional contact creation and follow-up/status changes.
- Duplicate email detection, including imports by different colleagues; source mailbox attribution.
- Paginated history and email bodies loaded only when opened.
- One-time migration of the current Stage spreadsheet snapshot, with preserved IDs and a reconciliation report.

The optional Gmail add-on is included with private installation instructions. FastBill API synchronization and ticket-system integration remain out of scope. The file importer stores reviewed email text and attachment names, not attachment files; the Gmail add-on transfers text and envelope fields only. No component sends, drafts, deletes, forwards or changes email.

## Quick local test with fictional data

Requires Docker with Compose. This uses a separate demo volume and binds only to localhost.

```sh
docker compose -f compose.local.yaml up -d --build
docker compose -f compose.local.yaml exec crm node server/cli.mjs user:add demo@example.test "Demo"
docker compose -f compose.local.yaml exec crm node server/cli.mjs demo
```

Choose a password of at least 12 characters at the hidden prompt, then open <http://localhost:3000>. Demo organisations and phone numbers are fictional. Use **E-Mail übernehmen** to select an `.eml` file or import the fixture generated by `node scripts/create-demo-email.mjs /tmp/demo.eml`. No real mailbox is accessed.

## Deploy behind your existing Traefik

The configuration uses the Glass Board conventions: `reverse-proxy`, `web-secure`, `letsencrypt`, and `default@file`. Your administrator sets DNS/TLS and can change these four Traefik values if necessary.

```sh
git clone https://github.com/ProgRies/stageforce.git
cd stageforce
cp .env.example .env
# Edit CRM_HOST in .env, for example crm.example.com.
docker compose up -d --build
docker compose exec crm node server/cli.mjs user:add you@example.com "Your Name"
```

The startup command builds the source locally. `.env` selects the local `stageforce:0.1.3` image; no registry account is required. A versioned registry image is available only after a successful release workflow. Open the HTTPS address and log in after creating the account. No default password, shared password or public registration exists.

All colleagues have equal CRM read/edit access. Each action uses their individual account. Account management is through CLI only. Local accounts do not grant access to a colleague's mailbox.

## Import the real CRM exactly once

The **separate private initial-data archive** contains `stage-crm-snapshot.json`. Keep it outside this source directory. It is a read-only capture of the spreadsheet, not a live connection. Do not import into the fictional demo database.

The initial spreadsheet import runs on the server through the CLI; it is not a browser upload. Your administrator performs it once. Afterward, colleagues edit records and import individual emails in the browser.

For a fresh production database (it may already contain your user account):

```sh
docker compose cp /absolute/private/path/stage-crm-snapshot.json crm:/app/data/initial-snapshot.json
docker compose exec crm node server/cli.mjs migrate /app/data/initial-snapshot.json /app/data/migration-report.json
docker compose cp crm:/app/data/migration-report.json ./migration-report.json
```

Review the report and compare selected records with the sheet. The same snapshot can be rerun safely; a different snapshot is refused once organisations exist. There is no merge/overwrite mode. The source spreadsheet remains untouched. Once your team accepts the migration, stop editing the old sheet; this CRM is the new source of truth. Preserve the private snapshot for audit/rollback and keep it out of Git.

An initial snapshot captures data at its export time. Later spreadsheet edits will not be included automatically. If the team continues editing the sheet before cutover, take a fresh snapshot and validate it before importing into a fresh production database.

Migration findings and schema are explained in [docs/schema.md](docs/schema.md). The private archive contains the report from the full migration validation.

## Record incoming and outgoing email

1. In Gmail, open the individual message's menu and select **Download message** (`Nachricht herunterladen`). For your reply, open the sent message, not the preceding incoming one.
2. In the CRM, select **E-Mail übernehmen** and choose the `.eml` file (up to 10 MB; up to ten files per selection).
3. Confirm the organisation, direction, date and text. Compare the original when quotations/inline replies are present. Optional: add a team summary, contact or next step.
4. Save. The email appears in the organisation's history. A duplicate adds only the importing colleague's source reference.

After replying in Gmail, import that sent message as well. Alternatively, add a quick **E-Mail gesendet** note with the date and outcome. There is no automatic detection of replies. Imported dates, not upload times, determine the last contact. Older email never advances the date backwards; missed calls and internal notes do not count as successful contact.

Source links are optional and do not grant mailbox access. Everyone sees the approved CRM text, while attachments and the original email remain in the source mailbox. Unconfirmed imports expire after 24 hours; quote removal is heuristic and always reviewable. There is no AI summarization.

## Accounts and backups

```sh
docker compose exec crm node server/cli.mjs user:add colleague@example.com "Colleague Name"
docker compose exec crm node server/cli.mjs user:password colleague@example.com
docker compose exec crm node server/cli.mjs user:disable colleague@example.com
docker compose exec crm node server/cli.mjs user:list
docker compose exec crm node server/cli.mjs backup /app/data/backups/crm-before-update.sqlite
docker compose cp crm:/app/data/backups/crm-before-update.sqlite ./crm-before-update.sqlite
```

Backups contain customer data. Put them in your existing restricted backup system. The CLI uses SQLite's consistent online backup API; do not copy the live `.sqlite` file alone while the application is writing. Restore steps: [docs/deployment.md](docs/deployment.md).

## Development and verification

Node 24.14+ within the 24.x line is required (native SQLite and TypeScript stripping).

```sh
npm ci --ignore-scripts
npm test
npm run typecheck
npm run build
APP_URL=http://localhost:3000 node server/http.mjs
```

The server serves the built UI; a separate frontend dev server is not required. Set `DATA_DIR` to choose a database directory. Run only one application instance for this initial version, with the volume on local server storage.

Tests use temporary SQLite databases and fictional data. They cover auth, CSRF/origin checks, conflicts, duplicate/retry protection, email parsing, rollback, migration, backups and call queues. Run `node scripts/smoke-container.mjs IMAGE` to verify a Docker image's login and restart persistence. The release workflow runs this check before publishing.

See [docs/release.md](docs/release.md) for source-only GitHub/GHCR publication.
